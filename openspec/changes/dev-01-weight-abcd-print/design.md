## Context

Основание и доказательства: [proposal.md](proposal.md), [explore.md](explore.md). УТ 11.6.2.68 на поддержке; нужен распространяемый через БСП печатный отчёт. XLSX содержит ошибки и используется как визуальный ориентир.

## Goals / Non-Goals

**Goals:** точный вес в кг, отдельный класс для товар/характеристика/упаковка, стандартная печать комплекта, понятный отказ до выдачи ошибочного результата.

**Non-Goals:** изменение движений отгрузки, анализ закупочных цен, редактирование товарной массы из отчёта, ABC по стоимости, настройка других границ классов.

## Decisions

### 1. Внешняя EPF с печатной командой БСП

Исходники внешней обработки хранить отдельно от типового `src/`, предлагаемый корень `external/WeightAbcdPrint/`; зарегистрировать отдельный source set Юники при реализации. Не смешивать внешнюю обработку с Configuration.xml. Двоичный EPF — сборочный артефакт.
Описание СведенияОВнешнейОбработке указывает назначение Документ.РеализацияТоваровУслуг и команду печати. Реализовать фактическую сигнатуру БСП после чтения её контракта в этой версии. КоллекцияПечатныхФорм и ОбъектыПечати заполняются стандартно, области привязываются к документам.
Альтернатива — встроенная печать расширения — отклонена: ТЗ явно требует механизм дополнительных отчётов и обработок.

### 2. Брутто и грузовая позиция

Пакетно читать брутто отгрузочной упаковки; массу товара без упаковки не использовать как замену. Коэффициенты количества и перевода массы в кг применять один раз. Ключ расчётной позиции — номенклатура + характеристика + упаковка; разные коробки одного товара получают собственные массы и классы. Повторы одного ключа объединять, количества складывать только в сопоставимых единицах.
Источник брутто в УТ, формулу перевода количества в отгрузочные упаковки и поведение пустой упаковки проверить до реализации; wiki их не определяет.

### 3. Накопленная доля с текущей позицией

S включает массу текущей грузовой позиции, W — общий вес. Классы: S/W <=50% — A, <=75% — B, <=90% — C, далее D. Первая позиция с 60% имеет B. Для весов 64/51/39/29/17 кг при порядке по убыванию накопленные доли 32/57,5/77/91,5/100%, классы A/B/C/D/D.
Сортировка по убыванию массы, разрешение равенств по представлениям и ссылкам, сравнение без округления остаются прежними проектными решениями; источники wiki не подтверждают эти детали. Их требуется уточнить, не смешивая с подтверждёнными границами.

### 4. Проверка до печати и макет

До формирования табличного документа собрать весь список нулевых/отсутствующих значений брутто упаковки, нулевых расчётных весов позиции и некорректных коэффициентов. При ошибке не выдавать классифицированную форму данного документа. Пустая отгрузка даёт понятное сообщение без деления на ноль.
Сохранить композицию XLSX: шапка, таблица, итог, свод классов/легенда. Добавить Характеристику; закупочную цену не выводить. Итоги считать из грузовых позиций без повторного включения массы. Отказ при нулевой массе и пустой отгрузке — прежняя защитная проектная политика; поведение отрицательной массы требует уточнения; источники подтверждают только отказ при отсутствии брутто.

## Risks / Trade-offs

- [Команда видна отдельно, но отсутствует в комплекте] → проверить регистрацию и фактический путь «Печать комплекта документов».
- [Разные схемы единиц и коэффициенты массы] → проверочные упаковки, граммы/кг, знаменатель не 1.
- [Большие документы] → пакетное чтение без запросов на каждую строку.
- [Искажённые демонстрационные числа XLSX] → отдельные эталоны ТЗ, зафиксированные в specs.

## Migration Plan

Собрать и проверить EPF в тестовой базе, подключить через БСП, назначить доступ логистам. Данных для миграции нет. Откат — отключение дополнительной формы; типовая печать продолжает работать.

## Open Questions

- Подтвердить контракт регистрации комплекта печати БСП и точный источник брутто/единиц массы в УТ.
- Уточнить формулу пересчёта количества в упаковки, сопоставление упаковок и пустую упаковку.
- Подтвердить сортировку, равные веса, округление долей и поведение при нулевой/отрицательной массе. Прежние технические решения сохранены как допущения, а не ответы wiki.
