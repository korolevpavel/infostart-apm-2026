## Проверенные факты УТ через Юнику

- `main:Document.ПланПродаж.Attribute`: Организация, Сценарий (Catalog.СценарииТоварногоПланирования), НачалоПериода, ОкончаниеПериода, Статус, Ответственный, Комментарий и другие поля.
- `main:Enum.СтатусыПланов.EnumValue`: Отменен, ВПодготовке, НаУтверждении, Утвержден.
- `main:Document.ПланЗакупок.Attribute` содержит организацию, сценарий, начало/окончание периода и статус.
- Полностью просмотренная `main:Document.ПланСборкиРазборки.Attribute` (26 полей) содержит сценарий/период/статус/склад, но НЕ Организацию. Простого запроса по одинаковому полю трёх документов недостаточно.
- Прочитан `main:Document.ПланПродаж.Module.Object.Method.ПередЗаписью.Body`, строки 247–372: ранний возврат при загрузке, даты запрета, вызов Планирование.ПроверитьСтатусУтвержден, пересчёт сумм и строк.
- Типовой флаг ДополнительныеСвойства «ПропуститьПроверкуЗапретаИзменения» относится к датам запрета, не является безопасным разрешением выборочной корректировки. Его нельзя использовать как токен.
- Поиск выявил обычную форму и форму самообслуживания. Серверный контроль должен покрывать обе и прямую запись.

## Выбор подхода

В расширении добавляем Организацию плану сборки/разборки и требуем её перед утверждением. Для старых утверждённых документов нужна отдельная подготовка данных; склад нельзя однозначно подменять организацией.
Начальный белый список полей — Ответственный и Комментарий из примера ТЗ. Организация, сценарий, период, статус, суммы, строки, дата/номер и служебные настройки не выдаются для корректировки.
Сервер хранит непрозрачное разрешение, привязанное к пользователю, сеансу, экземпляру формы, ссылке, версии объекта и выбранным полям. Клиентские галочки/свойства объекта не являются полномочием.

```text
Запрос полей → роль → зависимости → разрешение формы
Сохранение → версия → фактический diff → зависимости под блокировкой → запись + аудит
Закрытие формы → отзыв разрешения
```

## Риски и допущения

Пересечение включительно: НачалоЗависимого <= КонецПлана И КонецЗависимого >= НачалоПлана. Простое равенство месяцев непригодно.
Зависимость определяется условиями ТЗ, прямая ссылка на план продаж не обязательна.
Чтобы не было гонки между повторной проверкой и новым утверждением зависимости, нужен общий протокол блокировки по организации/сценарию на всех трёх типах.
Отказ не должен откатывать запись аудита вместе с транзакцией документа; нужен независимый устойчивый канал аудита.
Прямая запись без выданного разрешения запрещена; доверенный серверный маршрут может получить такое же разрешение и пройти те же проверки, не устанавливать флаг обхода.
Принимаем расширение как способ поставки для сохранения поддержки. Расширение списка полей сверх двух исходных — отдельное согласованное изменение.
