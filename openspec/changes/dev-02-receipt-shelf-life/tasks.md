- [ ] 1.1 Через Юнику проследить сбор серий при обычной и ордерной политике; найти точку контроля в приходном ордере для ордерной схемы и в приобретении для неордерной; уточнить отсутствие серий в самом ордере.
- [ ] 1.2 Прочитать точные контракты заимствования и обработчиков; создать CFE/source set extensions/ReceiptShelfLife с префиксом, сохранив поддержку main.
- [ ] 1.3 Заимствовать серию и соглашение; добавить полный срок хранения в днях, порог и признак настройки; повторно использовать ДатаПроизводства.
- [ ] 1.4 Определить подготовку существующих серий/соглашений и подтвердить хранение пустого значения/миграцию старых нулей, формулу дней/округление и день истечения; пустой порог — предупреждение, явный ноль — минимум 30%.

## 2. Серверный расчёт и формы

- [ ] 2.1 Реализовать валидатор даты изготовления/срока и синхронизацию ГоденДо без противоречащего ручного значения.
- [ ] 2.2 Реализовать календарный расчёт дней, неокруглённое сравнение и представление процента с одним знаком.
- [ ] 2.3 Нормализовать серии из строк/распределения и доступных складских связей; проверить полноту покрытия серийного количества.
- [ ] 2.4 Подключить проверку до движений приходного ордера при ордерной схеме и приобретения при неордерной, включая программное проведение/загрузку; приобретение без серий при ордерной схеме пропускать, чужой Отказ сохранять.
- [ ] 2.5 Добавить просмотр серии на выбранную дату и результатов серий документа; формировать сообщения с товаром, серией, фактом и эффективным минимумом; уточнить канал и показать список товаров без настройки ответственному за качество.
- [ ] 2.6 Согласовать порядок подключения с DEV-1C-03, чтобы обе проверки выполнялись без замены типового проведения.

## 3. Валидация и приёмка

- [ ] 3.1 Выполнить unica.check для новых/заимствованных объектов и BSL, git diff --check; получить актуальный контракт сборки через unica.run {}.
- [ ] 3.2 Собрать CFE и подключить в тестовую базу, заполнить контрольные серии/соглашение без изменения исторических данных автоматически.
- [ ] 3.3 Проверить срок 120 дней: 28 дней — разрешено, 35 — запрещено; 30 дней — точная граница; случай 74,96% и округлённые 75,0%.
- [ ] 3.4 Проверить пустые даты, срок 0/-1, будущее изготовление, просрочку, явный ноль (29% отказ/30% допуск), пустой порог (предупреждение при сохранении запрета просрочки), часы в датах.
- [ ] 3.5 Проверить несколько серий, распределение отдельной ТЧ, несерийные товары, смену даты, перепроведение и прямое проведение; при отказе подтвердить отсутствие частичных движений.
- [ ] 3.6 Проверить совместно с внеплановым приобретением DEV-1C-03 и записать входы/результаты, порядок настройки, миграции и отката.
