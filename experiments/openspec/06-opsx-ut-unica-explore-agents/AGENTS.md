# Шестой эксперимент с OpenSpec

## Процесс

- Используй OpenSpec 1.16.1 для Codex со схемой `spec-driven`.
- Сначала выполни отдельный этап `openspec-explore` с использованием Unica и субагентов. Только после завершения исследования переходи к `openspec-propose`.
- Используй только материалы этой папки. Не читай соседние папки, историю и результаты других экспериментов.
- Для исследования исходников 1С используй Unica и соответствующие скиллы. Каждый переход к обычному чтению исходников явно отмечай с указанием причины и области чтения.
- Во время исследования привлекай субагентов для разбора требований `ЗНР.docx`, исследования технических точек через Unica и независимой проверки выводов и пропущенных сценариев.
- Субагенты работают только на чтение. Основной агент объединяет результаты, проверяет обоснования и разрешает разногласия. Только основной агент записывает итоговые документы.
- Неустановленные бизнес-правила оставляй открытыми вопросами; не подменяй их предположениями.
- Документы пиши на русском языке, сохраняя обязательный синтаксис OpenSpec, включая структурные заголовки и ключевые слова `SHALL`/`MUST`.

## Ограничения

- Не изменяй исходники в `src/`.
- Не запускай сборку, обновление или информационную базу.
- Скиллы OpenSpec храни в `.agents/skills/`; не дублируй их в `.codex/skills/`.

## Коммиты

В каждый коммит, созданный при участии Codex, добавляй трейлер:

```text
Co-Authored-By: codex <codex@openai.com>
```
