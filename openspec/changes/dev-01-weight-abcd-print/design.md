## Context

Основание и доказательства: [proposal.md](proposal.md), [explore.md](explore.md). УТ 11.6.2.68 на поддержке; нужен распространяемый через БСП печатный отчёт. XLSX содержит ошибки и используется как визуальный ориентир.

## Goals / Non-Goals

**Goals:** точный вес в кг, одна классификация пары товар/характеристика, стандартная печать комплекта, понятный отказ до выдачи ошибочного результата.

**Non-Goals:** изменение движений отгрузки, анализ закупочных цен, редактирование товарной массы из отчёта, ABC по стоимости, настройка других границ классов.

## Decisions

### 1. Внешняя EPF с печатной командой БСП

Исходники внешней обработки хранить отдельно от типового `src/`, предлагаемый корень `external/WeightAbcdPrint/`; зарегистрировать отдельный source set Юники при реализации. Не смешивать внешнюю обработку с Configuration.xml. Двоичный EPF — сборочный артефакт.
Описание СведенияОВнешнейОбработке указывает назначение Документ.РеализацияТоваровУслуг и команду печати. Реализовать фактическую сигнатуру БСП после чтения её контракта в этой версии. КоллекцияПечатныхФорм и ОбъектыПечати заполняются стандартно, области привязываются к документам.
Альтернатива — встроенная печать расширения — отклонена: ТЗ явно требует механизм дополнительных отчётов и обработок.

### 2. Масса и агрегация

Одной пакетной выборкой получить строки и массу единицы хранения, нормализованную в кг по ВесЧислитель/ВесЗнаменатель/ВесЕдиницаИзмерения. Количество уже в единицах хранения; эквивалентный расчёт через КоличествоУпаковок использует коэффициент ровно один раз.
Разделить расчётные позиции (пара ссылок) и строки вывода (пара + единица). Суммы количества допустимы только внутри одной единицы. Общий вес пары определяет сортировку и класс; выводимые веса подстрок суммируются до веса пары. Единицу показывать из упаковки либо единицы хранения.
Массу брутто упаковки не подставлять вместо базовой массы без нового бизнес-решения.

### 3. Порог до позиции и точность

После сортировки по массе убыванию и представлению товара/характеристики возрастанию вычислить S — массу строго предшествующих пар, W — весь вес. Сравнивать 100*S с 50*W, 75*W, 90*W без округления процентов. Для одинаковых представлений дополнительный стабильный ключ — ссылки. Внутри пары единицы выводятся стабильно.
Альтернатива сравнения округлённой накопленной доли после позиции противоречит ТЗ и исключается.

### 4. Проверка до печати и макет

До формирования табличного документа собрать весь список нулевых/отсутствующих масс единицы, нулевых расчётных весов позиции и некорректных коэффициентов. При ошибке не выдавать классифицированную форму данного документа. Пустая отгрузка даёт понятное сообщение без деления на ноль.
Сохранить композицию XLSX: шапка, таблица, итог, свод классов/легенда. Добавить Характеристику; закупочную цену не выводить. Итоги считать из расчётных пар, не из повторённых подстрок класса.

## Risks / Trade-offs

- [Команда видна отдельно, но отсутствует в комплекте] → проверить регистрацию и фактический путь «Печать комплекта документов».
- [Разные схемы единиц и коэффициенты массы] → проверочные упаковки, граммы/кг, знаменатель не 1.
- [Большие документы] → пакетное чтение без запросов на каждую строку.
- [Искажённые демонстрационные числа XLSX] → отдельные эталоны ТЗ, зафиксированные в specs.

## Migration Plan

Собрать и проверить EPF в тестовой базе, подключить через БСП, назначить доступ логистам. Данных для миграции нет. Откат — отключение дополнительной формы; типовая печать продолжает работать.

## Open Questions

Блокирующих вопросов для предложения нет. При реализации подтвердить точный контракт регистрации комплекта БСП и источник коэффициента единицы веса. Если требуется масса упаковки брутто вместо базовой массы — изменить бизнес-контракт до реализации расчёта.
