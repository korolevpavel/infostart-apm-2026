## Context

См. [proposal.md](proposal.md), [explore.md](explore.md). Филиалы являются самостоятельными организациями, покупатели реализаций — контрагентами. XLSX задаёт композицию, но содержит пропуск даты и ошибки знаков.

## Goals / Non-Goals

**Goals:** один неизменяемый утверждённый лимит на головную организацию/месяц, ручной ввод/копирование, отчёт с корректным фактом и датами.

**Non-Goals:** запрет продаж при превышении лимита, исправление утверждённого лимита, бюджетирование подразделений, выборочная разблокировка по DEV-1C-06.

## Decisions

### 1. Новый документ и состояние

Отдельное CFE, предлагаемый каталог `extensions/BranchPurchaseLimits/`.
Документ МесячныйЛимитЗакупокФилиалов: ГоловнаяОрганизация (Catalog.Организации), Месяц (начало месяца), Состояние (Черновик/Утвержден), таблица Филиалы (ОрганизацияФилиал, ПлановаяСумма >=0). Валюта — управленческая, показывается пользователю; свободная валюта строки не вводится.
Утверждение — отдельная серверная команда с ролью; запрещены дубли филиалов, пустые ссылки и головная организация в роли собственного филиала.
После утверждения сравнивать сохраняемую версию целиком на сервере, запрещать изменение, отмену состояния, удаление/пометку, перепроведение с изменением и повторное заполнение во всех интерфейсах. Защита от прямой записи обязательна.
Альтернатива использования типового ПланаЗакупок меняет его семантику и не обеспечивает необратимость утверждения.

### 2. Уникальность утверждения

Служебный регистр утверждённых лимитов с ключом ГоловнаяОрганизация + Месяц, ссылка на документ. Команда утверждения блокирует ключ, перечитывает состояние и занятость, проверяет строки, пишет состояние/регистрацию в одной транзакции.
Черновиков может быть несколько. Повторный вызов утверждения уже утверждённого документа не создаёт второй факт. Два параллельных утверждения разных черновиков дают одного победителя.

### 3. Копирование

Для выбранной головной организации взять утверждённый документ непосредственно предыдущего календарного месяца. Скопировать только строки в новый черновик текущего месяца, не статус/ссылку/регистрацию утверждения. Подтвердить замещение имеющихся строк черновика в UI; сервер повторно проверяет, что целевой документ не утверждён.
Из-за уникальности утверждения «последний» источник за месяц однозначен. Если источника нет, сообщить и оставить ручной ввод.

### 4. Связь филиала и покупателя

Использовать явный регистр соответствия ОрганизацияФилиал ↔ Контрагент. Несколько контрагентов одного филиала допустимы, неоднозначность одного контрагента запрещена.
Регистр имеет период действия; факт операции сопоставляется на дату операции, чтобы последующая настройка не переносила историю между филиалами. Для возврата филиал берётся из исходной реализации, а дата/знак суммы — из возврата. Изменения исторических соответствий доступны только уполномоченному настройщику и меняют отчёт осознанно.
Альтернатива сопоставления по наименованию/ИНН ненадёжна и не используется.

### 5. Факт и матрица отчёта

Выбрать проведённые реализации выбранной головной организации и связанные проведённые возвраты. Учесть только товарные суммы после скидок с НДС (проектное допущение). Смешанный возврат распределить по строковым основаниям, не отнести всю сумму к одному филиалу.
Каждая операция даёт дату, филиал, подписанную сумму в валюте управленческого учёта. Пересчёт валюты — стандартный механизм УТ на дату операции; повторного пересчёта уже управленческих сумм не делать.
В отчёте СКД три набора: план по филиалу за выбранные полные месяцы; факт по филиалу; изменение факта по дню. План не соединять с каждой датой до суммирования, иначе он размножится.
Объединение филиалов плана и факта сохраняет нулевые планы. Даты динамические, календарно отсортированы, включая возвраты без отгрузки в этот день. Итог = сумма изменений; процент = общий факт / общий план *100, округление 1 знак; при нулевом плане «н/д».
Выбор периода — целые месяцы; возврат прошлого отгруженного месяца уменьшает факт месяца возврата.

## Risks / Trade-offs

- [Размножение плана JOIN по датам] → сначала отдельная агрегация, затем объединение.
- [Неизменяемый план содержит ошибку] → предварительная проверка/подтверждение утверждения; корректировка отдельной задачей по ТЗ.
- [Нестабильная связь организации и контрагента] → явная периодическая настройка.
- [Частичный/смешанный возврат] → проверка основания каждой суммы, исключение несвязанных возвратов.
- [Разные НДС/валюты] → один согласованный режим и типовые курсы.

## Migration Plan

Развернуть CFE, настроить соответствия и права, определить валюту управленческого учёта. Сначала заполнить тестовый черновик, проверить копирование и утверждение.
Эталон XLSX пересчитать из листа Операции: 9 150 000 план, 6 110 000 факт, 66,8%. Проверить ноябрьский пример Востока 1 300 000 / 1 500 000 = 86,7%.
Откат с утверждёнными данными требует резервной копии/выгрузки; отмену утверждения ради отключения не добавлять.

## Open Questions

Для предложения приняты суммы с НДС после скидок и явное соответствие филиалов контрагентам. При реализации уточнить типовой источник управленческих сумм и основания смешанных возвратов. При другом требовании по НДС сначала обновить спецификацию и эталоны.
