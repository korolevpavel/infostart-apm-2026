# Дашборд состояния ЗНР

Статический интерактивный обзор шести заданий УТ11. Данные берутся из текущих OpenSpec и LLM Wiki. Вопросы, задачи и счётчики извлекаются из файлов; краткие описания и замечания к макетам курируются в `build_snapshot.py`.

## Обновить данные

Из корня репозитория:

```sh
python3 sites/znr-overview/build_snapshot.py
```

Сборка запускает строгую проверку OpenSpec, копирует исходники `web/` в `dist/` и создаёт `dist/data.js`, `dist/snapshot.json` и единый `dashboard.html`. Время снимка — Europe/Moscow, версия — текущий HEAD основного репозитория. После изменения правил сверить курируемые описания и замечания в скрипте.

В Git хранятся `web/`, генератор, проверки и документация. Готовый `dashboard.html` включён в учебный комплект по решению автора. Весь `dist/`, локальная `.openai/` и временные файлы исключены через корневой `.gitignore`. Снимок содержит демонстрационные OpenSpec/wiki; после изменения документов пересоберите HTML перед коммитом.

Результаты проверки состава данных: [PRIVACY.md](PRIVACY.md).

## Открыть локально

Открыть `dashboard.html` в браузере: это один файл со встроенными стилями, данными и кодом. Зависимости и сервер не требуются. Также можно открыть `dist/index.html` рядом с остальными файлами `dist/`. Для локального HTTP-просмотра можно использовать `python3 -m http.server 8765 --directory sites/znr-overview/dist`.

## GitHub Pages

Планируемый адрес: https://korolevpavel.github.io/infostart-apm-2026/.

Workflow `Publish dashboards` сохраняет этот обзор как корневой `index.html` и добавляет сравнение экспериментов как `experiments/index.html`. Скрипт `sites/build_pages.py` копирует только два готовых HTML-файла; остальные файлы репозитория не отправляются в Pages. Встроенные в HTML тексты OpenSpec/wiki будут доступны посетителям сайта.

Пока репозиторий приватный, задание публикации пропускается, в том числе при ручном запуске. Настройки Pages сейчас не включаются. Видимость репозитория изменяет автор самостоятельно.

Первый запуск после открытия репозитория:

1. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Перейдите в **Actions → Publish dashboards → Run workflow**, выберите ветку `main` и запустите workflow.
3. Дождитесь успешного задания `deploy` и откройте адрес из результата deployment.

После этого изменения `sites/znr-overview/dashboard.html` и `sites/openspec-experiments/dashboard.html` в `main` публикуются автоматически. Изменения самого workflow также запускают публикацию. Ручной запуск разрешён только для `main` публичного репозитория.

Workflow не пересобирает снимок: после изменения OpenSpec/wiki выполните сборку и проверку из этой инструкции, затем закоммитьте HTML. Новые коммиты передавайте на GitHub через отдельную фильтрованную копию без истории `src/`.

После первой публикации проверьте загрузку сайта, поиск, открытие карточек и документов, экспорт JSON и переключение светлой/тёмной темы. До включения Pages проверка по конечному адресу не выполняется.

Документация GitHub: [настройка источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Содержание и ограничения

- Обзор портфеля, фильтры, поиск, карточки шести ЗНР.
- Дословные группы Open Questions, задачи с фактическими отметками и встроенное чтение Markdown-документов.
- 18 уточнений из сверки с wiki и ссылки на конспекты.
- Экспорт текущего снимка JSON.
- Светлая и тёмная темы: переключатель ☾/☀ в верхней панели, выбор сохраняется в браузере. При первом открытии используется системная тема; запрет локального хранилища не мешает переключению.
- Историческая диагностика Юники явно датирована; проверка в инфобазе не подразумевается.
- Материалы wiki демонстрационные. Комплектность артефактов не равна согласованию требований.
- Страница доступна в режиме чтения. Изменения исходных документов попадут в локальную версию после новой сборки.
- Бинарные DOCX/XLSX/PNG-оригиналы, журнал wiki, локальные настройки подключения и привязка аккаунта Sites в снимок не включаются.
- Автоматические обращения к Google Fonts и другим внешним ресурсам отсутствуют; используются установленные системные шрифты. Внешние ссылки в документах открываются только по нажатию.

Приватный Site зарегистрирован, идентификатор хранится в `.openai/hosting.json`. Публикация не выполнена: 05.11.2026 автоматическая проверка отклонила передачу внутренней документации во внешний Sites-репозиторий без явного разрешения пользователя на этот состав данных и назначение. Локальная версия полностью сохранена. Браузерный сервис был недоступен, поэтому визуальная проверка в браузере не выполнена. `verify.mjs` проверяет логику отображения, поиск, фильтры, карточки и ссылки на документы без браузера.
