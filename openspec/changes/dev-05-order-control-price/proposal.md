## Why

Менеджеру нужен актуальный при каждом проведении порог продажи с маржой 9% от выручки и серверный запрет продаж ниже него без отдельного полномочия и причины.

Основание: DEV-1C-05 — Контрольная цена в заказе клиента. Исследование, проверенные адреса Юники и допущения: [explore.md](explore.md).

## What Changes

- Сохраняемая контрольная цена строки, полученная из вида цены «Контрольная цена» с формулой «Закупочная / 0,91».
- Заполнение при ручном вводе и подборе, адресный пересчёт при изменении параметров цены, сохранение исторического значения при открытии и пересчёт всех проверяемых строк при каждом проведении; история используется только для аудита.
- Проверка фактической цены после скидок в сопоставимых валюте/единице/режиме НДС; отдельная роль и обязательная причина каждой строки ниже порога, очищаемая при копировании.

## Capabilities

### New Capabilities

- `order-control-price`: Контрольная цена в заказе клиента.

### Modified Capabilities

Нет: каталог основных спецификаций пока пуст.

## Impact

CFE: ЗаказКлиента и формы, виды цен/настройка формулы в данных, серверный модуль получения порога и контроля, роль разрешения и сохранённые построчные причины. Типовое ценообразование остаётся источником.

База: УТ 11.6.2.68, совместимость 8.3.27, Designer XML. Текущий change содержит только планирование; исходники `src/` не меняются.
